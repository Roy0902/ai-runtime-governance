## Highlights

- Multimodal guard input: text is evaluated; images are represented by
  `[image]`; other non-text input parts are discarded.
- Non-text model output parts are captured as readable markers; binary and
  invalid Unicode are sanitized before storage or export.
- Session timeline redesigned for readability: per-kind event styling, a trace
  summary strip, compact cards, and details on expand.
- Lazy loading for event content, trace pages, prompts and model usage, with
  explicit load-more buttons.
- Gateway continuation recovery after activity records expire or are cleared.
- Initial page-load overlay blocks interaction until session initialization
  completes.

## Requirements

- Java 25
- PostgreSQL 17
- Optional: Keycloak 26 for SSO/BFF sign-in
- Optional: SMTP server for account verification and password-reset email

## Quick start

1. Create a PostgreSQL database and set `GOVERNANCE_DB_URL`,
   `GOVERNANCE_DB_USER`, `GOVERNANCE_DB_PASSWORD` and `GOVERNANCE_PORT`.
2. Run `java -jar ai-runtime-governance-backend-0.2.0.jar`.
3. Serve `frontend/` from a static web server and reverse-proxy `/api/` to the
   backend on the same origin.
4. Open the frontend URL after `/actuator/health` reports `UP`.

See `README.md` and `docs/BACKEND.md` inside the archive for configuration,
Keycloak and deployment details.

## Known limitations

- A PostgreSQL database is required; the backend does not start without it.
- A model provider and gateway configuration are required for guarded model
  traffic.
- Interactive prompt approval is not part of this release.
- The frontend must be served behind a reverse proxy that sends `/api/` to the
  backend; opening the static files directly is not sufficient.
